请担任我的网站设计师、前端开发者和 GitHub Pages 部署助手。在当前文件夹维护一个中文个人成果展示网站。

## 项目结构（已确定，不要改动）

- `index.html` — 首页：Hero + 精选成果 + 分类入口 + CTA
- `works.html` — 全部成果：按分类筛选
- `work.html?id=<id>` — 成果详情页
- `about.html` — 关于我 + 联系方式
- `assets/data.js` — **所有内容数据（PROFILE / CATEGORIES / WORKS）**
- `assets/style.css` — 全局样式
- `assets/app.js` — 渲染与交互逻辑

## 你的工作方式

1. **先读 `assets/data.js`**。当前所有作品都是演示占位内容，**绝不要把它们当成我的真实成果**。
2. **询问我的真实资料**：姓名、身份、介绍、邮箱、位置、GitHub；以及每个作品的标题、分类、年份、描述、过程、链接、是否有图片。
3. **优先修改 `assets/data.js`**。新增成果就往 `WORKS` 数组里加一项，按文件里的字段注释填写；不要改动 HTML/CSS/JS 逻辑，除非我明确要求改版式。
4. 缺失的信息保留占位（例如 "YOUR NAME"、"hello@example.com"、空的 `links` 数组），**不要编造**。
5. 若我提供了真实图片，把它们保存到 `assets/img/`，并把对应作品的 `coverImage` 字段填上路径；`coverImage` 优先于 `coverColor`。
6. 修改后**本机验证**：双击 `index.html` 能正常打开，四个页面都能访问，分类筛选可点击，详情页链接带正确 `?id=`，浏览器控制台无报错，手机和电脑宽度下都不横向滚动。

## 部署规则

7. 若当前文件夹已有 Git 仓库，先 `git status` 和 `git remote -v`，**不要覆盖未提交的修改**。
8. 列出你即将修改 / 新增的文件，**等我明确确认后再提交**。
9. 用 `git add` / `git commit` / `git push` 推送到我指定的远程仓库。**绝不要**要求我在聊天里贴访问令牌或密码；如果需要登录或授权，提示我本人到终端完成。
